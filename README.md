# Companion — 자취생을 위한 냉장고 관리 AI 컴패니언

자취생의 **냉장고 재고를 기억**해, **뭘 해먹을지 함께 정해주는** 모바일 앱.
있는 재료와 식성을 기억하고, 지금 만들 수 있는 요리를 추천한다.

> 목표: 로컬 토이가 아니라 **실제 스토어 배포 + 진짜 유저 확보 + 서비스 운영 경험.** (수익은 보너스)

---

## 무엇인가

범용 챗봇에 매번 "냉장고에 뭐 있어"를 붙여넣는 것과 다르다. 핵심은 **"내 냉장고를 아는 상태에서 요리를 돕는다"** 이고, 아래 셋이 **차별점이자 북극성**이다. 하나라도 빠지면 그냥 ChatGPT 래퍼다.

1. **기억** — 재고·식성·알레르기·조리도구를 기억해 매번 다시 묻지 않는다. 특히 **재고는 상태가 계속 변해서, 앱이 들고 있지 않으면 기능 자체가 성립하지 않는다.** 기억이 장식이 아니라 필수 인프라다.
2. **능동적 구조화 질문** — 답만 뱉지 않고, 부족한 조건(몇 인분·조리시간·오늘 뭐가 당기는지)을 되물어 구조화한다.
3. **있는 재료로 추천 + 안전** — 냉장고에 있는 것 + 유통기한 임박한 것 우선으로 요리를 제안하고, **알레르기·못 먹는 재료는 절대 넣지 않는다.**

왜 냉장고인가 — 구매 결정 같은 저빈도 도메인은 리텐션이 약하고 기억이 없어도 돌아간다(=래퍼). 냉장고는 **주 단위로 돌아오고**, 상태가 계속 변해 기억을 들고 있어야만 작동한다.

---

## 첫 도메인: 냉장고 관리 + 레시피 추천

```
사용자: "장 보고 왔어. 계란 한 판이랑 대파, 삼겹살 샀어"
  → 재료를 재고에 등록 + 유통기한 자동 추정 (삼겹살 3일, 대파 7일, 계란 3주)

사용자: "오늘 뭐 해먹지?"
  → 냉장고 재고 + 임박 재료 확인 (삼겹살이 곧 상함)
  → 부족한 조건 능동 질문 (몇 인분? 시간은?) — 이미 아는 식성·알레르기는 안 물음
  → 있는 재료로 만들 수 있는 요리 추천 + 임박 재료 먼저 쓰게 유도

사용자: "삼겹살 구이 만들었어"
  → 재고에서 삼겹살 차감 (잘못 차감되면 냉장고 화면에서 되돌리기)
```

## 원칙 (흔들리지 않게 못 박은 것)

- **"컴패니언" = 나를 기억하는 개인화**, 연인 롤플레이가 아니다. 기억하는 대상은 **사용자**(냉장고 재고·식성·알레르기·조리도구)이지 AI 캐릭터가 아니다. → 상세 캐릭터 설정(관계·성별·연인 페르소나)은 **조언자 톤 + 사용자 프로필**로 축소한다.
- **v1 스코프 = 재고 + 유통기한 + LLM 레시피 추천.** 외부 API 의존 0 — 레시피 검색은 v1.1로 미룬다(슈퍼앱 함정 방지). v1의 생사는 레시피 품질이 아니라 **"유저가 재고를 입력하고 유지하는가"** 이므로, 외부 변수 없이 그것부터 검증한다.
- **알레르기는 안전 문제.** 정렬 취향과 급이 다르다 — 모델이 놓치면 사람이 다친다. 프롬프트에서 별도로 강조하고 임박 우선 규칙보다 우선시한다.
- **현재 비상업** — 광고·어필리에이트 없음. 그래서 네이버 오픈 API(레시피 검색)를 쓸 수 있다. **수익화하는 순간**이 곧 그 이용 조건을 다시 확인해야 하는 트리거다.
- **확보 우선** — 매일 오는 유저가 아니라 "장 볼 때·끼니 정할 때" 오는 유저부터 확보한다.

---

## 로드맵

1. **냉장고 관리 + 레시피 추천** (첫 출시, v1) — 재고 기억 + 유통기한 + 능동 질문 + 있는 재료 기반 추천 + 알레르기 안전
2. **v1.1 레시피 리서치** — 사용자가 **"자세한 레시피"를 요청할 때만** 네이버 검색으로 실제 글을 찾아 카드로 보여준다. 유튜브는 그다음(쿼터가 하루 100회뿐이라 요리명 캐싱이 함께 필요)
3. **수익화** — 어필리에이트 전환 (그 시점에 네이버 오픈 API 이용 조건 재확인)

## 기술 스택

- **모바일**: React Native + Expo + TypeScript (`apps/native-companion`)
- **백엔드**: NestJS + Postgres + Prisma (`apps/nest-companion`)
- **LLM**: OpenAI / Gemini — 벤더 라우터(`LlmService`)가 모델 이름으로 자동 분기. 채팅 중 tool-use 로 재고를 등록·차감한다.
- **공유 타입**: `@companion/types` (클라↔서버 API 계약)
- **모노레포**: pnpm workspace

레포 규칙·아키텍처 세부는 각 `AGENTS.md` 참고 (루트 = 전체, `apps/*/AGENTS.md` = 앱별).

## 현재 상태

- ✅ 인증(JWT access+refresh), LLM 벤더 추상화(OpenAI/Gemini), 장기 메모리(식성·알레르기·조리도구) 추출·주입, **냉장고 재고**(별도 테이블·유통기한 추정·채팅 tool-use 등록/부분 차감/soft delete)·**레시피 추천**·**알레르기 안전 주입**, 냉장고 탭·홈 "먼저 먹어요"·온보딩, 회원탈퇴
- ✅ v1.1 **레시피 검색** 종단 완료: `recipe/`(네이버 웹문서 검색) → 채팅 툴 `search_recipes`(서버가 즉시 실행하는 종결 툴) → 툴 결과로 저장 → 앱 `RecipeResultCard` 블록(0건·검색실패도 같은 블록). 남은 건 "다른 레시피 더"(페이징)이고, 필요해질 때 넣는다
- 🚧 배포 전 미완: 로그인/회원가입 **rate limit**(`@nestjs/throttler`), 임시 실험 엔드포인트(`GET /gemini`·`GET /openai`) 정리
- 방향 이력: 감정 컴패니언(캐릭터챗) → 구매 의사결정 에이전트 → **자취생 냉장고 관리 컴패니언.** 인프라(인증·LLM 라우터·메모리·툴콜 루프·모바일)는 그대로 재활용. 상품 검색(구 `commerce/`)은 v1.2 로드맵과 함께 제거했고, 그 네이버 호출 계층이 `recipe/` 의 뼈대가 됐다.
