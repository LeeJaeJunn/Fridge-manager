# Companion — 나를 기억하는 AI 의사결정 컴패니언

대학생의 **상황·취향을 기억**해, 여러 분야의 **의사결정을 도와주는** 모바일 앱.
첫 출시 도메인은 **구매 결정**이고, 이후 다른 결정 영역으로 확장한다.

> 목표: 로컬 토이가 아니라 **실제 스토어 배포 + 진짜 유저 확보 + 서비스 운영 경험.** (수익은 보너스)

---

## 무엇인가

단발성 검색이나 범용 챗봇과 다르다. 핵심은 **"나를 아는 상태에서 결정을 돕는다"** 이고, 아래 셋이 **차별점이자 북극성**이다. 하나라도 빠지면 그냥 ChatGPT 래퍼다.

1. **기억** — 취향·예산·과거 선택을 기억해 매번 다시 묻지 않는다.
2. **능동적 구조화 질문** — 답만 뱉지 않고, 부족한 정보를 되물어 조건을 구조화한다.
3. **실제 데이터로 비교** — 막연한 조언이 아니라 실제 선택지를 조회·비교하고 **이유를 제시**한다.

---

## 첫 도메인: 구매 의사결정 에이전트

대학생의 구매 결정을 돕는다. "선풍기 조회해서 나열"이 아니라:

```
사용자: "선풍기 필요해"
  → 기존 취향·예산 기억 확인
  → 부족한 정보 능동 질문 ("방 크기는? 예산대는? 소음 민감해?")
  → 구매 조건 구조화
  → 상품 API 조회 → 적합 후보 추출
  → 최종 후보 비교 → 개인화 추천 + 이유 제시
```

---

## 원칙 (흔들리지 않게 못 박은 것)

- **"컴패니언" = 나를 기억하는 개인화**, 연인 롤플레이가 아니다. 기억하는 대상은 **사용자**(취향·예산·이력)이지 AI 캐릭터가 아니다. → 상세 캐릭터 설정(관계·성별·연인 페르소나)은 **조언자 톤 + 사용자 프로필**로 축소한다.
- **v1 스코프 = 구매 결정만.** 아키텍처는 범용 "의사결정 엔진"이지만, v1에 여행·공부·수강신청 등 다른 도메인을 넣지 않는다(슈퍼앱 함정 방지).
- **현재 비상업** — 광고·어필리에이트 없음. 그래서 네이버 오픈 API 를 상품 데이터에 쓸 수 있다. **수익화하는 순간**이 곧 상품 API 를 제휴형(쿠팡 파트너스 등)으로 교체해야 하는 트리거다.
- **확보 우선** — 매일 오는 유저가 아니라 "필요할 때 쓰는" 유저부터 확보한다. 리텐션은 이후 기능으로 키운다.

---

## 로드맵

1. **구매 의사결정 에이전트** (첫 출시) — 기억 + 능동 질문 + 상품 비교 + 이유
2. **의사결정 도메인 확장** — 여행·자취·공부 등, **데이터 접근이 확인되는 것부터**
3. **수익화** — 어필리에이트 전환 (+ 상품 API 제휴형 교체)

---

## 기술 스택

- **모바일**: React Native + Expo + TypeScript (`apps/native-companion`)
- **백엔드**: NestJS + Postgres + Prisma (`apps/nest-companion`)
- **LLM**: OpenAI / Gemini — 벤더 라우터(`LlmService`)가 모델 이름으로 자동 분기
- **공유 타입**: `@companion/types` (클라↔서버 API 계약)
- **모노레포**: pnpm workspace

레포 규칙·아키텍처 세부는 각 `AGENTS.md` 참고 (루트 = 전체, `apps/*/AGENTS.md` = 앱별).

---

## 현재 상태

- ✅ 인증(JWT access+refresh), LLM 벤더 추상화(OpenAI/Gemini), 장기 메모리 추출·주입, 상품 검색(네이버)+채팅 내 tool-use 추천, 회원탈퇴, 모바일 앱 골격
- 🔄 **방향 전환 중**: 감정 컴패니언(캐릭터챗) → **구매 의사결정 에이전트.** 캐릭터 설정은 "조언자 + 사용자 프로필"로 축소 예정, 기억은 취향·예산·구매이력 중심으로.
